# 화면 정의서 — 의료기기 유통 플랫폼 (MediTrade)

> **⚠️ 프로젝트명**: MediTrade (잠정 확정 — 동명 업체 존재로 추후 변경 가능)
>
> 기능 정의서(`functional-spec.md`)의 기능과 매핑되는 화면을 정의한다.
> 웹(Next.js)·앱(React Native) 공통 기준이며, 관리자 화면은 웹 전용이다.

---

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 목적 | 각 화면의 구성·입력·동작·전환·예외를 정의 |
| 화면 ID | `SCR-그룹-순번` (그룹: COM 공통 / BUY 구매자 / SEL 판매자 / ADM 관리자) |
| 우선순위 | P1(MVP) / P2(확장) / P3(고도화) — 기능 정의서와 동일 |
| 플랫폼 | 웹·앱 공통(반응형), 관리자=웹 전용 |

### 화면 명세 표기 규칙
- **권한**: 공개 / BUYER / SELLER / ADMIN / 인증(로그인 필요)
- **입력 항목**: 필드 / 타입 / 필수 / 검증
- **동작**: 사용자 액션 → 처리 → 연결 API 또는 전환 화면
- **연관 기능**: `functional-spec.md`의 기능 ID

## 3. 화면 흐름 (네비게이션)

```
[COM-001 홈/상품목록]
   ├─ 검색/필터 ─────────────→ (목록 갱신)
   ├─ 상품 클릭 ─────────────→ [BUY-002 상품 상세]
   │                               ├─ (구매자) 문의하기 → [BUY-004 문의/견적 요청]
   │                               ├─ (구매자) 미팅 요청 → [BUY-008 미팅 요청]
   │                               └─ (비로그인) 문의/미팅 시 → [COM-002 로그인]
   ├─ 로그인 ────────────────→ [COM-002] ─→ (성공) 역할별 홈
   └─ 회원가입 ──────────────→ [COM-003]

[로그인 후]
  (BUYER)  마이 → [COM-004] → 찜[BUY-003]/문의[BUY-005]/거래[BUY-006]
  (SELLER) 마이 → [COM-004] → 내상품[SEL-001] → 등록[SEL-002]
                              → 받은문의[SEL-004] → 견적발송[SEL-005] → 거래[SEL-006]
                              → 받은미팅[SEL-008] → 응답/일정조정[SEL-009] → (확정)
  (ADMIN)  → [ADM-001 대시보드] → 각 관리 화면
```

## 4. 주요 화면 상세 (Phase 1)

### COM-002 로그인
- **권한**: 공개
- **목적**: 이메일/비밀번호로 로그인하고 JWT 토큰을 저장한다.
- **구성요소**: 로고, 이메일 입력, 비밀번호 입력, [로그인] 버튼, [회원가입] 링크, [비밀번호 찾기] 링크(P2)
- **입력 항목**

  | 필드 | 타입 | 필수 | 검증 |
  | --- | --- | --- | --- |
  | email | text | ○ | 이메일 형식 |
  | password | password | ○ | 비어있지 않음 |

- **동작**: [로그인] → `POST /api/v1/auth/login` → 성공 시 accessToken 저장(앱: SecureStore / 웹: httpOnly 쿠키 권장) → 역할별 홈으로 이동
- **예외**: 401 → "이메일 또는 비밀번호가 올바르지 않습니다."(계정 존재 여부 비노출) / 네트워크 오류 토스트
- **연관 기능**: AUTH-002

### COM-003 회원가입 (역할 선택)
- **권한**: 공개
- **목적**: 역할(구매자/판매자)을 선택하고 계정을 만든다.
- **구성요소**: 역할 선택 토글(BUYER/SELLER), 이메일, 비밀번호, 비밀번호 확인, 이름, 연락처(선택), 약관 동의 체크, [가입] 버튼
- **입력 항목**

  | 필드 | 타입 | 필수 | 검증 |
  | --- | --- | --- | --- |
  | role | select | ○ | BUYER \| SELLER |
  | email | text | ○ | 이메일 형식, 중복 불가 |
  | password | password | ○ | 8자 이상 |
  | passwordConfirm | password | ○ | password와 일치 |
  | name | text | ○ | 1자 이상 |
  | phone | text | ✕ | 숫자/하이픈 |
  | agreeTerms | checkbox | ○ | 동의 필수 |

- **동작**: [가입] → 클라이언트 검증 → `POST /api/v1/auth/signup` → 성공 시 로그인 화면으로 이동(또는 자동 로그인). SELLER는 가입 후 "사업자 인증 필요(P2)" 안내.
- **예외**: 409(이메일 중복) → 필드 하단 메시지 / 400(VALIDATION_ERROR) → 필드별 메시지
- **연관 기능**: AUTH-001

### COM-001 / BUY-001 홈 · 상품 목록/검색
- **권한**: 공개
- **목적**: 판매중 상품을 탐색하고 검색·필터·정렬한다.
- **구성요소**:
  - 상단: 검색 입력창, 카테고리 진입, (P2) 필터 버튼(상태/가격대/지역/제조사), 정렬 드롭다운
  - 본문: 상품 카드 그리드/리스트(대표 이미지, 상품명, 모델명, 상태 뱃지, 가격 또는 "문의")
  - 하단: 페이지네이션 또는 무한 스크롤
- **입력 항목**: keyword(검색어), page, size, (P2) 필터/정렬 파라미터
- **동작**:
  - 진입/스크롤/검색 → `GET /api/v1/products?page=&size=&keyword=`
  - 카드 클릭 → [BUY-002 상품 상세]
- **빈 상태**: 결과 없음 → "조건에 맞는 상품이 없습니다." + 필터 초기화 버튼
- **예외**: 로딩 스켈레톤, 오류 시 재시도 버튼
- **연관 기능**: SRCH-001/002/003/004

### BUY-002 상품 상세
- **권한**: 공개 (문의는 BUYER 로그인 필요)
- **목적**: 상품의 스펙·이미지·판매자 정보를 확인하고 문의로 진입한다.
- **구성요소**:
  - 이미지 갤러리(대표+추가)
  - 기본 정보: 상품명, 모델명, 제조사, 상태(신품/중고/리퍼), 가격 또는 "가격 문의", 지역
  - 스펙 테이블(key-value: 출력/채널수/인증번호 등)
  - 상세 설명
  - 판매자 정보(상호, 평점·리뷰 수 — P2)
  - 하단 고정: [문의/견적 요청] 버튼, [미팅 요청] 버튼, [찜](P2)
- **동작**:
  - 진입 → `GET /api/v1/products/{id}`
  - [문의] → 로그인 상태+BUYER면 [BUY-004], 비로그인이면 [COM-002]로 유도
  - [미팅 요청] → 로그인 상태+BUYER면 [BUY-008], 비로그인이면 [COM-002]로 유도
- **예외**: 404 → "삭제되었거나 존재하지 않는 상품입니다." + 목록으로
- **연관 기능**: PROD-004

### BUY-008 미팅 요청 (P2)
- **권한**: BUYER
- **목적**: 판매자에게 미팅(온라인/방문/현장 실사)을 요청한다.
- **구성요소**: 대상 판매자/상품 표시, 미팅 유형 선택, 목적 선택, 희망 일시 후보(최대 3) 추가 UI, 메모, [요청 보내기] 버튼
- **입력 항목**

  | 필드 | 타입 | 필수 | 검증 |
  | --- | --- | --- | --- |
  | meetingType | select | ○ | ONLINE \| VISIT_SELLER \| VISIT_BUYER |
  | purpose | select/text | ○ | 상담/실물확인/데모/설치상담 등 |
  | preferredSlots | datetime[] | ○ | 1~3개, 미래 시점 |
  | location/onlineLink | text | ✕ | 유형에 따라(온라인=링크, 방문=주소) |
  | message | textarea | ✕ | ~1000자 |

- **동작**: [요청 보내기] → `POST /api/v1/meetings` (status=REQUESTED) → 성공 시 [BUY-009]로 이동 + 토스트, 판매자에게 알림(NOTI-004)
- **예외**: 미인증 401 → 로그인 / 입력오류 400 `VALIDATION_ERROR` / 판매자 없음 404
- **연관 기능**: MEET-001

### BUY-009 내 미팅 요청 목록 (P2)
- **권한**: BUYER
- **목적**: 보낸 미팅 요청의 상태를 확인하고 확정/취소한다.
- **구성요소**: 요청 카드(판매자/상품, 유형, 상태 뱃지, 희망/확정 일시), 상태 필터
- **동작**:
  - 진입 → `GET /api/v1/meetings?role=buyer`
  - 판매자가 ACCEPTED/RESCHEDULE_PROPOSED 시 → [확정](MEET-005) 또는 [취소](MEET-006)
- **빈 상태**: "보낸 미팅 요청이 없습니다."
- **연관 기능**: MEET-004/005/006

### SEL-001 내 상품 목록
- **권한**: SELLER
- **목적**: 판매자가 본인 상품을 관리한다.
- **구성요소**: [상품 등록] 버튼, 상품 행(이미지, 상품명, 상태, 가격, 조회수, [수정][삭제]), 상태 필터
- **동작**:
  - 진입 → 본인 상품 조회(판매자용 목록 API, P1은 `GET /products` 확장 또는 별도 엔드포인트)
  - [수정] → [SEL-002] (수정 모드) / [삭제] → 확인 모달 → `DELETE /api/v1/products/{id}`
- **빈 상태**: "등록한 상품이 없습니다." + [첫 상품 등록하기]
- **예외**: 삭제 시 본인 상품 아님 403 처리
- **연관 기능**: PROD-005/002/003

### SEL-002 상품 등록/수정
- **권한**: SELLER
- **목적**: 상품을 신규 등록하거나 기존 상품을 수정한다.
- **구성요소**: 이미지 업로더(P2), 입력 폼, [임시저장](P2)/[등록] 버튼
- **입력 항목**

  | 필드 | 타입 | 필수 | 검증 |
  | --- | --- | --- | --- |
  | name | text | ○ | 1~200자 |
  | modelName | text | ✕ | ~100자 |
  | categoryId | select | ○ | 유효 카테고리 |
  | conditionType | select | ○ | NEW \| USED \| REFURBISHED |
  | price | number | ✕ | 0 이상(미입력 시 "문의") |
  | priceNegotiable | checkbox | ✕ | - |
  | region | text | ✕ | ~50자 |
  | description | textarea | ✕ | - |
  | images | file[] | ✕(P2) | 이미지 형식/용량 |

- **동작**:
  - 등록 → `POST /api/v1/products` (status=ON_SALE)
  - 수정 → `PUT /api/v1/products/{id}`
  - 성공 → [SEL-001]로 이동 + 토스트
- **예외**: 400(VALIDATION_ERROR) 필드별 표시 / 미인증 401 / 권한 403
- **연관 기능**: PROD-001/002

### SEL-008 / SEL-009 받은 미팅 요청 · 응답 (P2)
- **권한**: SELLER
- **목적**: 받은 미팅 요청을 확인하고 수락(일시 택일)·거절·일정 재제안한다.
- **구성요소**:
  - SEL-008 목록: 요청 카드(구매자/상품, 유형, 목적, 희망 일시 후보, 상태), 상태 필터
  - SEL-009 응답: 희망 일시 중 택일 라디오, [수락 확정] / [거절] / 새 일시 제안 입력 + [재제안]
- **동작**:
  - 목록 → `GET /api/v1/meetings?role=seller`
  - 수락(택일) → `PATCH /api/v1/meetings/{id}` (status=ACCEPTED + 선택 일시) → 구매자 알림(NOTI-004)
  - 거절 → status=REJECTED / 재제안 → status=RESCHEDULE_PROPOSED + 제안 일시
  - 확정은 양측 합의 시 CONFIRMED(MEET-005)
- **빈 상태**: "받은 미팅 요청이 없습니다."
- **예외**: 타인 요청 접근 403 / 없음 404
- **연관 기능**: MEET-002/003/005

### COM-004 마이페이지
- **권한**: 인증
- **목적**: 역할별 메뉴 진입점.
- **구성요소**: 프로필(이름/이메일/역할), 메뉴 목록(역할별), [로그아웃]
  - BUYER: 찜 / 내 문의 / 거래 내역
  - SELLER: 내 상품 / 받은 문의 / 받은 미팅 / 거래 관리 / 사업자 인증(P2)
- **동작**: 각 메뉴 → 해당 화면 / [로그아웃] → 토큰 삭제 → [COM-001]
- **연관 기능**: MBR-001

| 컴포넌트 | 설명 |

| 글로벌 헤더/탭바 | 웹=상단 헤더, 앱=하단 탭바(홈/검색/마이) |
| 상품 카드 | 이미지·상품명·상태 뱃지·가격("문의" 포함) |
| 상태 뱃지 | 신품/중고/리퍼, 판매중/품절 색상 구분 |
| 토스트/알럿 | 성공·실패 피드백(공통 응답 message 표시) |
| 확인 모달 | 삭제·취소 등 파괴적 동작 전 확인 |
| 로딩 스켈레톤 | 목록/상세 로딩 표시 |
| 빈 상태 뷰 | 데이터 없음 안내 + 주요 액션 |
| 폼 필드 + 에러 | 필드 하단 검증 메시지(서버 VALIDATION_ERROR 매핑) |

## 6. 공통 UX 규칙

- **응답 처리**: 모든 API 응답은 `{ success, code, message, data }`. 실패 시 `message`를 사용자에게 노출하되 내부 상세는 표시하지 않음.
- **로딩**: 목록·상세는 스켈레톤, 버튼 동작은 로딩 스피너 + 중복 클릭 방지(disable).
- **에러**: 네트워크/500 → 재시도 버튼. 401 → 로그인 화면 유도(토큰 만료 포함).
- **빈 상태**: 결과 0건은 항상 안내 문구 + 다음 액션 제공.
- **페이지네이션**: 기본 page=1, size=20. 앱은 무한 스크롤, 웹은 페이지 또는 더보기.
- **가격 표기**: price=null이면 "가격 문의", 협의 가능 시 "협의 가능" 뱃지.
- **권한 가드**: 비로그인/권한없음 진입 시 적절히 로그인 유도 또는 접근 차단.
- **접근성**: 터치 타깃 최소 44px, 폼 라벨/포커스 명확, 색상만으로 정보 전달 금지.
